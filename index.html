Four data sources

What each Vicmap product contains, and what we use

These are four official Victorian government geodatabases, not four copies of the same table. Each answers a different question. We only keep the layers and fields the count needs.

Property · VMPROP.gdb

Lots and plans

Contains: every titled parcel, property polygons, the parcel–property bridge, centroids, easements, road casements.

We use: V_PARCEL_MP lot/plan fields, PARCEL_PROPERTY (parcel → property), CENTROID for the zone join.

Step 3 · Admin join

303 is a council code. Banyule is the council’s name.

Banyule is a local government area in Melbourne’s north-east (Heidelberg, Rosanna, and nearby suburbs). It is not a dataset. It is the council this land sits in. Vicmap Property only stores the number PARCEL_LGA_CODE = 303. Join that to Vicmap Admin LGA_POLYGON to get the name BANYULE. Victoria has 79 councils in our headline file; Banyule is one of them (1,727 of the 45,057). We used Banyule as the pilot because the statewide extract had to match something smaller first.

Step 6 · Pick one label

Why we do not take the most common string

The parent property 424071430 is linked to every parcel, so ALFREDA AVENUE can win a simple mode. That is a street name, not a findable address.

We score each string, keep the highest score on the plan, then take the first unit among ties. Units beat house numbers; house numbers beat a bare road.

ALFREDA AVENUE × 4 links

Statewide

Same joins, every plan

Unzip a new Vicmap dump and rerun the script. The method does not change. The total is how many plans survive this path — currently 45,057.

  • PARCEL_PLAN_NUMBER groups lots into a scheme
  • PARCEL_LGA_CODE = LGA_CODE → council
  • PARCEL_PFI → PARCEL_PROPERTY
  • PROPERTY_PFI → ADDRESS
  • PLAN_ZONE centroid within zone → residential flag
